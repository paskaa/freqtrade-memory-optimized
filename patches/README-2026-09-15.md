# 2026-09-15 FreqUI / API 提速改动备份

针对「FreqUI 打开时 Bot comparison / Open Trades 很久才出数」做的三项改动。
改动已经**部署到实盘**，这里是备份 + 一键重放，防止 freqtrade 更新（重装 venv 包）后被冲掉。

## 背景：实盘跑的不是源码树

实盘 import 的是 venv 里的一份 freqtrade 副本：

```
/root/ft_userdata/.venv/lib/python3.12/site-packages/freqtrade/   # ← 实盘真正运行的代码（2026.8）
/root/freqtrade/                                                  # 源码树（2026.9-dev），不参与运行
```

所以：**只改 `/root/freqtrade` 对实盘无效**；UI 静态文件同理，实盘用的是
`…/site-packages/freqtrade/rpc/api_server/ui/installed/`。

## 本次三项改动

| # | 改动 | 落点 | 是否需要重启 |
|---|---|---|---|
| 1 | FreqUI 只加载最近 500 笔成交（新设置，可改 Unlimited） | UI 构建产物 | 否（静态文件实时读取） |
| 2 | API 响应 gzip 压缩（>1KB，`enable_gzip` 默认开） | `webserver.py` 热补 | **是** |
| 3 | 刷新间隔可配（默认仍是 5s / 60s） | UI 构建产物 | 否 |

实测：`/trades` 单页 1.39MB → 187KB（gzip），一次刷新窗口 7.60MB → 0.36MB。

## 文件说明

- `apply_runtime.sh` —— **更新后跑这个**（幂等，会自动备份原文件）：
  ```bash
  bash /root/ft_userdata/patches/2026-09-15_freqapi_perf/apply_runtime.sh
  systemctl restart freqtrade      # gzip 需重启；UI 不需要
  ```
- `freqtrade-runtime-gzip.diff` —— 打在 venv 副本上的实际 diff（对照 `.bak_20260915_145346`）
- `freqtrade-gzip.patch` —— 源码树上的 git 提交（含 config_schema / docs / 测试），已推送到
  `paskaa/freqtrade` 分支 `api-gzip`，目标上游 PR；也是本改动的长期归宿
- `frequi-trade-limit-and-refresh.patch` / `frequi-source.diff` —— FreqUI 源码改动
  （PR: <https://github.com/freqtrade/frequi/pull/3042>，fork: `paskaa/frequi` 分支 `perf/limit-trade-history`）
- `web_ui_dist.tar.gz` —— 构建好的 FreqUI 产物，直接解包覆盖 `ui/installed/` 即可

## 从源码重建 UI（需要改动 UI 时）

```bash
cd /root/frequi && git checkout perf/limit-trade-history
npx vite build
tar czf /root/ft_userdata/patches/2026-09-15_freqapi_perf/web_ui_dist.tar.gz -C dist .
cp -r dist/{assets,favicon.ico,index.html,_redirects} \
      /root/ft_userdata/.venv/lib/python3.12/site-packages/freqtrade/rpc/api_server/ui/installed/
```

## 注意

- FreqUI 默认只加载最近 500 笔成交：仪表盘 Closed Trades、Trade History 页、Cumulative Profit
  曲线都只看得到这 500 笔；要完整历史在设置里选 `Unlimited`。
  取数必须带 `order_by_id=false`（按平仓时间倒序），否则拿到的是**最老**的 500 笔。
- 若将来 upstream 合并了 gzip PR，或 freqtrade 版本升级到自带压缩，`apply_runtime.sh` 会因为
  检测到 `GZipMiddleware` 已存在而自动跳过，不会重复打补丁。
